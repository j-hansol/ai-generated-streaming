# 실시간 강의 방송 만들기 — 강의 커리큘럼

> Node.js · React · WebRTC로 나만의 온라인 강의실을 처음부터 만들어 보는 8회 과정

| 항목 | 내용 |
|---|---|
| 대상 | JavaScript 기초 문법(변수, 함수, 배열·객체, `async/await`)을 아는 입문자 |
| 분량 | 8회 × 2시간 (총 16시간) |
| 결과물 | 브라우저에서 화면 공유·웹캠으로 송출하고, 수강생이 실시간으로 시청·채팅하는 온라인 강의실 |
| 교재 코드 | 이 저장소 (`apps/server`, `apps/web`, `packages/shared`, `media/`) |
| 준비물 | Windows/macOS PC, Chrome, Node.js 24+, pnpm, VS Code, 웹캠(선택) |

---

## 1. 과정 목표

과정을 마치면 수강생은 다음을 할 수 있습니다.

1. 실시간 방송이 **어떤 단계(캡처 → 인코딩 → 전송 → 재생)** 로 이루어지는지 설명한다.
2. WebRTC와 HLS의 **지연 시간·확장성 차이**를 직접 측정하고 상황에 맞게 고른다.
3. **Fastify + SQLite**로 REST API 서버를 만들고, 외부 서버(MediaMTX)의 API와 연동한다.
4. **React**로 목록·폼·실시간 갱신 화면을 만든다.
5. 브라우저 API(`getUserMedia`, `getDisplayMedia`, `RTCPeerConnection`)로 **영상 송출(WHIP)과 시청(WHEP)** 을 직접 구현한다.
6. **WebSocket**으로 채팅·질문·손들기 같은 실시간 상호작용을 만든다.
7. **로그인과 역할(강사/수강생)** 에 따라 송출·시청 권한을 제어한다.

## 2. 수업 진행 방식 (매 회 2시간)

| 시간 | 구성 | 설명 |
|---|---|---|
| 0:00 – 0:10 | 복습 · 퀴즈 | 지난 시간 핵심 3가지, 과제 확인 |
| 0:10 – 0:50 | 개념 강의 | 슬라이드로 원리 설명 (그림 위주) |
| 0:50 – 1:05 | 시연 | 완성된 앱에서 오늘 만들 기능을 먼저 보여줌 |
| 1:05 – 1:50 | 실습 | 단계별로 직접 코딩 (막히면 완성 코드와 비교) |
| 1:50 – 2:00 | 정리 · 과제 | 핵심 요약, 다음 시간 예고, 과제 안내 |

**실습 운영 팁**

- 매 회 시작 시점의 코드를 Git 브랜치(`session-01` … `session-08`)로 나눠 두면, 뒤처진 수강생도 바로 따라올 수 있습니다.
- 실습은 **"동작하는 것부터 → 이유 이해 → 개선"** 순서로 진행합니다. 처음부터 완벽한 코드를 요구하지 않습니다.
- 송출/시청 시험은 **Chrome 창 두 개를 나란히** 띄워서 합니다. (탭으로 겹치면 가려진 탭이 느려져 헷갈립니다.)

## 3. 회차별 계획

### 1회. 실시간 방송은 어떻게 동작할까 — 원리와 개발 환경

| 구분 | 내용 |
|---|---|
| 학습 목표 | 방송의 4단계(캡처·인코딩·전송·재생)와 지연 시간의 의미를 설명한다. 개발 환경을 갖추고 완성본을 실행한다. |
| 핵심 개념 | 코덱(H.264, Opus), 비트레이트·해상도·프레임, 프로토콜 비교(RTMP·HLS·WebRTC), 전체 구조도 |
| 시연 | 완성된 앱으로 테스트 화면 송출 → 다른 창에서 시청 → 시계로 지연 측정 |
| 실습 | Node·pnpm 설치 확인 → 저장소 받기 → MediaMTX 배치 → `pnpm dev` 실행 → 강의실 만들고 송출·시청 |
| 과제 | WebRTC와 LL-HLS의 지연을 각각 3번 측정해 표로 정리 |

### 2회. 모노레포와 API 서버 — Fastify + SQLite

| 구분 | 내용 |
|---|---|
| 학습 목표 | pnpm 모노레포 구조를 이해하고, REST API로 강의실 CRUD를 만든다. |
| 핵심 개념 | 모노레포·워크스페이스, TypeScript 타입 공유(`packages/shared`), HTTP 메서드와 상태 코드, Fastify 라우트·스키마 검증, `node:sqlite` |
| 시연 | 브라우저 개발자 도구 Network 탭으로 API 요청·응답 보기 |
| 실습 | `GET/POST/DELETE /api/classrooms` 구현 → 잘못된 요청(빈 제목)이 400이 되는지 확인 |
| 과제 | 강의실에 "강사 이름" 필드 추가 (DB → API → 타입) |
| 교재 코드 | `apps/server/src/routes.ts`, `classrooms.ts`, `db.ts`, `packages/shared/src/index.ts` |

### 3회. 미디어 서버 연동 — MediaMTX

| 구분 | 내용 |
|---|---|
| 학습 목표 | 미디어 서버의 역할을 이해하고, 설정 파일과 제어 API로 방송 상태를 가져온다. |
| 핵심 개념 | 미디어 서버가 하는 일(수신·변환·배포), 경로(path) 규칙, 포트와 보안, 제어 API(`/v3/paths/list`), 방송 상태·시청자 수 합치기 |
| 시연 | `curl`로 MediaMTX API를 직접 호출해 송출 전/후 결과 비교 |
| 실습 | `mediamtx.ts` 작성 → 목록 API에 `live` 정보 붙이기 → 방송 중 삭제 시 송출 강제 종료 |
| 과제 | (선택) OBS로 RTMP 송출해 보고, WebRTC 시청 시 소리가 안 나는 이유 조사 |
| 교재 코드 | `media/mediamtx.yml`, `apps/server/src/mediamtx.ts` |

### 4회. React로 화면 만들기 — 강의실 목록

| 구분 | 내용 |
|---|---|
| 학습 목표 | 컴포넌트·상태·효과의 개념을 익히고, 서버 데이터를 주기적으로 갱신하는 화면을 만든다. |
| 핵심 개념 | Vite 개발 서버와 프록시, JSX와 컴포넌트, `useState`·`useEffect`, 커스텀 훅(`usePolling`), 라우팅(react-router) |
| 시연 | 다른 창에서 송출을 시작하면 목록의 배지가 LIVE로 바뀌는 모습 |
| 실습 | 강의실 목록 → 만들기 폼 → 삭제 확인 UI → LIVE 배지 |
| 과제 | 목록에 "방송 시작 후 경과 시간" 표시 |
| 교재 코드 | `apps/web/src/pages/ClassroomListPage.tsx`, `hooks.ts`, `api.ts`, `main.tsx` |

### 5회. WebRTC로 송출하기 — WHIP

| 구분 | 내용 |
|---|---|
| 학습 목표 | 브라우저에서 화면·카메라를 가져와 미디어 서버로 송출한다. 연결이 맺어지는 과정을 설명한다. |
| 핵심 개념 | `MediaStream`과 트랙, `getUserMedia`·`getDisplayMedia`, `RTCPeerConnection`, SDP offer/answer, ICE 후보, WHIP 규격, 코덱 우선순위 |
| 시연 | `chrome://webrtc-internals`에서 연결 상태·후보 쌍 관찰 |
| 실습 | `whip.ts`·`webrtc.ts` 작성 → 강사 화면에서 테스트 화면/웹캠/화면 공유 송출 → 송출 통계 표시 |
| 사례 학습 | "신호 교환은 됐는데 `connecting`에서 멈춘다" — ICE 경로 문제를 찾고 고친 실제 디버깅 과정 |
| 과제 | 송출 해상도(720p/1080p) 선택 기능 추가 |
| 교재 코드 | `apps/web/src/lib/webrtc.ts`, `whip.ts`, `testPattern.ts`, `pages/TeachPage.tsx` |

### 6회. 시청하기 — WHEP와 LL-HLS

| 구분 | 내용 |
|---|---|
| 학습 목표 | 두 가지 방식으로 방송을 재생하고, 지연·안정성 차이를 실험으로 확인한다. |
| 핵심 개념 | WHEP, HLS의 원리(플레이리스트·세그먼트), LL-HLS, hls.js, `getStats()`로 품질 측정, 자동 재연결 |
| 시연 | 같은 방송을 WebRTC/LL-HLS로 나란히 재생하며 시계 비교 |
| 실습 | `whep.ts` 작성 → 시청 화면 → 방식 전환 버튼 → 방송 종료/재시작 시 자동 재연결 |
| 과제 | 지연 측정 결과를 그래프로 그리고 "어떤 수업에 어떤 방식이 맞는지" 한 문단으로 정리 |
| 교재 코드 | `apps/web/src/lib/whep.ts`, `stats.ts`, `pages/WatchPage.tsx` |

### 7회. 실시간 소통 — WebSocket 채팅·질문·손들기

| 구분 | 내용 |
|---|---|
| 학습 목표 | WebSocket으로 강의실 단위의 실시간 메시지를 주고받는다. |
| 핵심 개념 | HTTP 폴링 vs WebSocket, 방(room) 관리, 메시지 형식 설계(공유 타입), 브로드캐스트, 재접속 처리, 도배 방지 |
| 시연 | 두 창에서 채팅·손들기가 실시간으로 반영되는 모습 |
| 실습 | 서버에 WebSocket 엔드포인트 → 채팅 → 질문 등록·답변 완료 → 손들기 → 접속자 목록 |
| 과제 | 채팅 슬로우 모드(3초에 1번) 구현 |
| 교재 코드 | 2단계에서 추가 (`apps/server/src/ws.ts`, `apps/web/src/components/Chat.tsx` 예정) |

### 8회. 로그인과 권한, 그리고 마무리

| 구분 | 내용 |
|---|---|
| 학습 목표 | 역할(강사/수강생)에 따라 송출·시청·채팅 권한을 제어하고, 프로젝트를 정리·발표한다. |
| 핵심 개념 | 비밀번호 해시, JWT, 역할 기반 권한, MediaMTX HTTP 인증 훅, 보안 점검 목록 |
| 시연 | 수강생 계정으로 송출을 시도하면 거부되는 모습 |
| 실습 | 회원가입·로그인 → 강의실 소유자만 송출 → MediaMTX 인증 훅 연결 |
| 마무리 | 미니 프로젝트 발표(5분/팀), 다음 단계 안내(녹화·다시보기, SFU, HTTPS 배포) |
| 교재 코드 | 2단계에서 추가 (`apps/server/src/auth.ts`, MediaMTX `authMethod: http` 예정) |

> **참고:** 7·8회 내용은 저장소의 **2단계** 구현에 해당합니다. 현재 저장소에는 1단계(1~6회 범위)까지만 구현되어 있으므로, 7·8회 수업 전에 2단계를 완성해 두어야 합니다.

## 4. 평가 (예시)

| 항목 | 비율 | 내용 |
|---|---|---|
| 회차별 과제 | 40% | 매 회 과제 제출 (동작 여부 중심) |
| 미니 프로젝트 | 40% | 아래 목록에서 하나를 골라 구현 후 발표 |
| 참여 | 20% | 실습 참여, 질문, 동료 도움 |

**미니 프로젝트 주제 예시**

- 화면 공유 위에 강사 웹캠을 작게 겹쳐 보내기 (Canvas 합성)
- 수강생 반응 버튼(👍❓) — 강사 화면에 실시간 집계
- 강의 타이머·쉬는 시간 알림
- 출석 기록(입장·퇴장 시각)과 CSV 내보내기
- 투표·퀴즈 기능

## 5. 수업 전 강사 체크리스트

- [ ] 실습실 PC에 Node.js 24+, pnpm, Chrome 설치 확인
- [ ] MediaMTX 실행 파일을 미리 내려받아 배포 (인터넷이 느린 환경 대비)
- [ ] Windows 방화벽 경고가 뜨면 "취소"해도 된다고 안내 (같은 PC 안의 연결은 동작)
- [ ] 회차별 시작 코드 브랜치 준비 (`session-01` … `session-08`)
- [ ] 웹캠이 없는 수강생은 "테스트 화면"으로 실습
